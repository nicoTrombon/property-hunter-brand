Privacy Policy

Effective 21 October 2026

Barcelona Property Hunter is a personal apartment-discovery application operated by the owner of the dedicated Gmail account. It is not offered as a public service and does not accept third-party account registrations. Contact: property.hunter.es@gmail.com.

Information accessed

After the account owner grants consent, the application uses the Gmail API's gmail.readonly permission. This permission technically permits reading mailbox messages; the application's collection logic searches for Idealista property-alert subjects from its notification sender within a rolling 30-day window.

For matching messages, it reads message identifiers, timestamps, sender headers and message bodies to extract property links and listing details. It checks the Gmail account's email address to ensure the configured inbox is used.

How information is used

Google user data is used only to identify property alerts, extract apartment details, avoid processing the same message twice, maintain price history, rank candidate apartments and generate the owner's private reports. The ingestion component does not modify mailbox messages, labels or read status. An optional, separately authorized sending component sends the daily report to the email address configured by the owner.

Google user data is not sold, used for advertising, used to train generalized artificial-intelligence or machine-learning models, or shared with data brokers. Use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Daily email delivery

The optional delivery component requests Gmail send permission plus OpenID and email identity scopes to verify the sending account. Its OAuth token is stored separately from the read-only ingestion token. It sends extracted property information and report calculations to the single recipient configured by the owner, using Gmail. The recipient address and sending status, date and message identifier are retained in the private SQLite database to reduce duplicate sends. The recipient’s email provider processes and retains received messages according to that account’s settings. To stop digest delivery, disable the digest setting or remove the sending token from GitHub Actions; existing messages remain in the sender’s and recipient’s mailboxes until deleted there.

Storage and service providers

Extracted listing fields may include a property identifier, canonical URL, title, neighborhood text, price, area, room counts and other supplied attributes. These fields, observation history and processed Gmail message identifiers and timestamps are stored in SQLite in a private GitHub repository. Reports are stored privately in that repository and may be uploaded as GitHub Actions artifacts.

The pipeline does not intentionally persist full email bodies, recipient tracking parameters or email attachments. Listing titles and descriptive text may contain addresses or information supplied by the property advertiser. Google provides the Gmail API; GitHub hosts the private code, workflow execution, database history and report artifacts. These providers process data as needed to deliver their services under their own terms and privacy policies. The account owner and people explicitly granted access to the private repository can access stored records.

OAuth credentials are kept outside source control and provided to GitHub Actions through an encrypted repository secret. Access tokens are refreshed in memory during workflow execution. An authorization token may also remain on the owner's trusted local machine.

Retention and deletion

Listing records and price history are retained until the owner deletes them; there is currently no automatic retention cutoff. The 30-day Gmail search window is not a deletion policy. Git history, workflow logs and artifacts may preserve older copies according to GitHub settings and retention rules.

To remove stored information, the owner must delete the relevant database and report records and, where required, remove historical Git copies and workflow artifacts. Removing a current file alone does not erase prior Git versions. For a data-access or deletion question, contact property.hunter.es@gmail.com.

Revoking Gmail access

The account owner can revoke the application's authorization in Google Account connections, remove the GitHub Actions secret and disable the scheduled workflow. Revoking access prevents future authorized Gmail collection; it does not automatically delete previously stored data.

This public website

This static information site is hosted by GitHub Pages. It has no sign-in, Gmail connection, forms, advertising or application analytics, and sets no application cookies. GitHub may process standard connection and request information when serving the site; see the GitHub Privacy Statement.

Changes

This policy will be updated when the application's data practices change. The effective date above identifies the current version.
